# ADR-004: Gráficos de relatórios construídos à mão (CSS/SVG), sem lib de charts

## Status

Accepted

## Date

2026-07-24

## Context

A Onda 4 traz relatórios visuais: barras e cartões de estatística, conforme `design/reference-components/Metrics.jsx` — que implementa medidores e barras com elementos dimensionados por percentual, sem biblioteca. O projeto não tem lib de charts hoje, e o único tipo de gráfico que o design define é barra simples.

## Decision

Implementar os gráficos como **componentes próprios em CSS/SVG** (`Meter`, `BarChart`, `StatCard` dentro do kit `metrics`), com elementos dimensionados por percentual e cores exclusivamente dos tokens. Nenhuma dependência de charting.

## Alternatives Considered

### Alternative 1: Recharts (ou lib similar)

- **Description**: Adotar uma lib declarativa de charts para os relatórios.
- **Pros**: Eixos, tooltips e novos tipos de gráfico prontos para evolução futura.
- **Cons**: ~100kb+ de bundle numa app que roda em celular de voluntário; theming da lib precisa ser domado para respeitar os tokens (risco direto de cor literal); o design não pede nada além de barras.
- **Why rejected**: YAGNI — uma dependência inteira para renderizar retângulos proporcionais.

## Consequences

### Positive

- Zero dependência nova; fidelidade total aos tokens (cores, `.num` mono tabular, movimento do DS).
- Bundle continua leve para o contexto de campo.

### Negative

- Se relatórios futuros exigirem gráficos complexos (linhas, séries múltiplas, tooltips ricos), será preciso reavaliar — decisão registrada para esse momento.

### Risks

- Nenhum relevante no escopo atual; a superfície é pequena e testável por unit test (percentual → largura).

## Implementation Notes

Dados vêm de `GET /api/reports/attendance` (existente, sem mudança). Números sempre com tipografia mono tabular. Animações de preenchimento respeitam `prefers-reduced-motion`.
