# ADR-007: Playwright para captura do baseline visual, fora do CI

## Status

Accepted

## Date

2026-07-24

## Context

O PRD exige baseline visual: capturas de todas as telas ao fechar cada onda, servindo de referência contra regressões futuras, com a questão aberta de quem guarda e onde. O projeto não tem Playwright nem ferramenta de screenshot; as alternativas eram capturas manuais versionadas ou um script Playwright reproduzível.

## Decision

Adicionar **Playwright como dependência dev** com um script de captura (`frontend/scripts/capture-baseline.ts`): navega as rotas com viewports fixos (mobile 390×844, desktop 1280×800), autentica com credencial de desenvolvimento e salva as capturas em `docs/visual-baseline/<onda>/`. Roda **manualmente no fechamento de cada onda**, contra o stack local (backend + dados de dev) — fora do CI, para não exigir backend seedado no pipeline.

## Alternatives Considered

### Alternative 1: Capturas manuais versionadas

- **Description**: Capturar telas à mão no fechamento de cada onda e commitar em `docs/visual-baseline/`.
- **Pros**: Zero dependência nova; serve à conferência humana.
- **Cons**: Viewports e estado inconsistentes entre capturas; processo tedioso e sujeito a esquecimento; não reexecutável.
- **Why rejected**: Decisão do usuário — preferiu capturas reproduzíveis e a porta aberta para E2E futuro.

## Consequences

### Positive

- Capturas consistentes e reexecutáveis (mesmo viewport, mesmas rotas); base pronta para evoluir a testes E2E/regressão visual em iniciativa futura.

### Negative

- Dependência dev pesada (~browsers do Playwright); o script depende de backend local rodando com dados de desenvolvimento razoáveis.

### Risks

- **Dados locais variáveis** tornam capturas não comparáveis pixel a pixel — aceitável: o baseline é referência humana de conferência, não diff automatizado. Se virar regressão visual automatizada no futuro, aí sim exigirá seed determinístico (decisão para essa iniciativa).

## Implementation Notes

Instalado na Fase 0 junto com o script; rotas cobertas crescem a cada onda (auth → catequista → inscrição → admin). Captura das telas do catequista inclui o estado offline simulado (`context.setOffline`) para registrar o chip de rede e a fila.
