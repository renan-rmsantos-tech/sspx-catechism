# ADR-006: Ícones PWA pré-gerados e versionados no repositório

## Status

Accepted

## Date

2026-07-24

## Context

A marca existe como SVG em `design/assets/` (`brasao.svg`, `brasao-claro.svg`, `app-icon.svg`, `favicon.svg`). O manifest PWA precisa de PNGs raster (192/512, maskable) para instalação confiável no Android; hoje há apenas um `pwa.svg` provisório em `frontend/public/`. A questão: gerar os rasters no build ou uma única vez, versionados.

## Decision

Gerar **uma vez** os PNGs a partir do `app-icon.svg` — `pwa-192.png`, `pwa-512.png`, `pwa-maskable-512.png` (com área de segurança de ~20% para o maskable) e `apple-touch-icon.png` (180) — e commitá-los em `frontend/public/`, junto de uma cópia do `favicon.svg`. O manifest e o `index.html` referenciam os arquivos estáticos. Os PNGs são artefato derivado: se a marca mudar, regeneram-se a partir do SVG — nunca são editados à mão.

## Alternatives Considered

### Alternative 1: Geração no build (@vite-pwa/assets-generator)

- **Description**: Preset do vite-pwa gera os PNGs do SVG a cada build.
- **Pros**: Ícones sempre sincronizados com o SVG fonte.
- **Cons**: Dependência dev pesada (sharp), tempo de build, configuração — para assets que praticamente nunca mudam.
- **Why rejected**: Automação contínua para um evento raro; o custo permanente não paga o benefício.

## Consequences

### Positive

- Zero dependência de build; resultado inspecionável no PR; manifest simples apontando para estáticos.

### Negative

- Mudança de marca exige lembrar de regenerar — mitigado pela nota no próprio manifest/README e pela regra "artefato derivado" registrada aqui.

### Risks

- **Maskable mal enquadrado** (brasão cortado no Android) — mitigado validando com as ferramentas de preview de maskable antes de commitar.

## Implementation Notes

Geração pontual via ferramenta local (ex.: `rsvg-convert`/`sharp-cli`) documentada no commit. O precache do service worker (`globPatterns` já inclui `png,svg`) absorve os arquivos automaticamente.
