# ADR-003: Portar os reference-components do DS como componentes próprios em TypeScript

## Status

Accepted

## Date

2026-07-24

## Context

A biblioteca de componentes hoje é mínima: `frontend/src/components/ui/` tem só `button.tsx` (custom sobre `@base-ui/react/button`, com hex inline no hover) e `card.tsx` (um `<div>`). O `components.json` do shadcn (estilo `base-nova`) está configurado, mas nenhum componente de prateleira foi instalado.

O design system entrega 7 reference-components em `design/reference-components/*.jsx` (Button, Chip, Field, AttendanceRow, Metrics, ReviewDrawer, Sidebar) que **codificam regras de produto** que componentes genéricos não têm: botão desabilitado exige motivo (`disabledLabel`), `aria-invalid` como único hook de estilo de erro, `mark: null` como estado real e contável na chamada, chips `-soft`/`-ink`, drawer não-modal com sombra exclusiva, sidebar que colapsa para faixa horizontal (nunca hamburger), gráficos em CSS puro com `role="img"`.

## Decision

Traduzir os 7 reference-components para `.tsx` como **componentes próprios** em `frontend/src/components/ui/`, com tipos estritos que tornam as regras do DS incompiláveis de violar (ex.: union discriminada exigindo `disabledLabel` quando `disabled`). `@base-ui/react` entra só onde há interação não-trivial (ReviewDrawer sobre Base UI Dialog; Select da `Field` família se necessário). O shadcn CLI permanece configurado, mas nenhum componente de prateleira é instalado nesta iniciativa. Os gráficos (`Bars`, `Meter`) seguem a referência: CSS puro, **sem biblioteca de gráficos**.

## Alternatives Considered

### Alternative 1: shadcn como base + restyle

- **Description**: Instalar os componentes shadcn equivalentes (button, badge, input, sheet, table, sidebar…) e ajustá-los ao DS por cima.
- **Pros**: Acessibilidade e manutenção "de fábrica"; padrão conhecido pela comunidade.
- **Cons**: Cada componente exigiria retrabalho profundo para as regras do DS (disabledLabel, um teal, tally com null); o resultado divergiria tanto do upstream que o benefício de atualização se perde; mais código instalado do que o necessário.
- **Why rejected**: As regras comportamentais do DS são a parte difícil, e os .jsx de referência já as implementam — partir do shadcn seria portar as regras do mesmo jeito, só que sobre uma base maior.

### Alternative 2: Híbrido por componente

- **Description**: Portar do DS os componentes com regra de negócio e usar shadcn para utilitários (table, select, dialog, label).
- **Pros**: Cada peça vem da fonte mais barata.
- **Cons**: Duas origens de código e dois estilos de manutenção para uma biblioteca pequena (~10 arquivos); tabela e label do DS são triviais de portar.
- **Why rejected**: A economia não compensa a heterogeneidade numa biblioteca deste tamanho.

## Consequences

### Positive

- Comportamento fiel ao DS por construção — os .jsx de referência são a especificação executável.
- Tipos estritos transformam regras inegociáveis em erro de compilação, não de revisão.
- Dependências não crescem (Base UI e cva já estão no projeto; nenhuma lib de gráficos entra).

### Negative

- Manutenção 100% própria — nenhum upstream para receber correções de acessibilidade.
- Componentes utilitários (table, select) são escritos à mão em vez de instalados.

### Risks

- **Deriva ao traduzir JSX→TSX** (classes CSS do DS → utilities Tailwind sobre tokens). Mitigação: conferência lado a lado contra `design/ui_kits/app/components.html` como critério de saída da Fase 0; testes de comportamento por componente (ADR-005).
- **Acessibilidade regredir vs. primitives prontos**. Mitigação: Base UI Dialog onde foco/Esc/scrim importam; testes RTL de `aria-*`.

## Implementation Notes

- `button.tsx` e `card.tsx` atuais são **substituídos** (o variant `hover:bg-[#78350F]` morre com eles).
- Exports auxiliares testáveis acompanham os componentes: `tallyMarks`, `isRejectionValid`, `ConfirmAttendanceButton`, `NetworkChip`.
- `design/reference-components/` e `design/ui_kits/app/components/` são idênticos byte a byte — qualquer um serve de origem; usar `design/reference-components/`.
