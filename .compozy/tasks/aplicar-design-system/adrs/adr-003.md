# ADR-003: Componentes-âncora com utilities Tailwind + CVA

## Status

Accepted

## Date

2026-07-24

## Context

O `AGENTS.md` determina que os `.jsx` de referência sejam adaptados para TypeScript + shadcn, mas deixa em aberto o *como* das classes: traduzir cada classe do `catequese-ds.css` para utilities Tailwind, ou portar o CSS de componente (adaptado aos tokens) para um `@layer components` com wrappers React finos. O único componente estilizado hoje (`components/ui/button.tsx`) já usa o padrão CVA (class-variance-authority) sobre utilities.

## Decision

Estilizar todos os componentes-âncora com **utilities Tailwind sobre os tokens do tema, organizadas com CVA** no padrão shadcn — variants tipadas (`variant`, `size`), `className` passthrough via `cn()`. Nenhum CSS de componente em `@layer components` além de utilitários de tipo genuinamente globais (ex.: `.num`).

## Alternatives Considered

### Alternative 1: CSS de componente adaptado + wrappers finos

- **Description**: Portar as classes do `catequese-ds.css` (adaptadas aos tokens) para `@layer components` e criar wrappers React que aplicam `.btn btn-primary` etc.
- **Pros**: Fidelidade máxima à referência com mínima tradução; menos conferência visual.
- **Cons**: Duas linguagens de estilo convivendo (utilities no app, classes de componente nos âncora); a fronteira com o "importar a folha crua" que o `AGENTS.md` proíbe fica ambígua; variantes sem tipagem.
- **Why rejected**: Contraria o espírito da regra do `AGENTS.md` ("a implementação final é TypeScript + shadcn") e fragmenta o idioma do codebase.

## Consequences

### Positive

- Idiomático ao stack — o `button.tsx` atual já é o molde; tree-shaking natural; variants tipadas.
- A guarda de "zero cor literal" fica trivial: basta procurar hex/rgb nos `.tsx`.

### Negative

- A tradução classe→utility é manual e exige conferência visual componente a componente contra `design/ui_kits/app/components.html`.

### Risks

- **Deriva na tradução** (espaçamento ou sombra "quase igual") — mitigada pelo critério de saída da Fase 0: validação lado a lado contra as referências antes de abrir a Onda 1.

## Implementation Notes

Componentes em `frontend/src/components/ui/`: `button` (reescrito), `chip`, `field` (+input/select/textarea), `card` (variantes), `attendance-row`, `seg`, `choice`, `table`, `metrics`, `empty-state`, `stepper`, `sidebar`, `drawer` (sobre `@base-ui/react` Dialog, já dependência), `brand`. Comportamento interativo vem do Base UI onde existir primitivo; estilo é 100% utilities+tokens.
